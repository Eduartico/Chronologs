# Chronologs — Personal Finance Local Observability Platform

A local-first personal finance system with real connectors, automation, and analytics. Aggregates all financial data into a unified append-only event ledger.

**No cloud dependencies. No external database. File-based persistence. Fully auditable. All personal data stays in a gitignored local folder.**

## Quick Start

```bash
npm install
cd web && npm install && cd ..
npx playwright install chromium   # only needed for the Pricempire connector
npm run dev
```

Open **http://localhost:5173** in your browser. The server runs on `http://localhost:3001` with the API at `/api`.

The app starts empty. On first run it creates a `user-data/` folder — that is **your** data and it never goes to git.

## Architecture

```
EVENT → PROJECTION → VIEW
```

Every data write is an event appended to `user-data/ledger/events.ndjson`. Projections are rebuilt by replaying the ledger (cached in memory, invalidated on write). Nothing stores "final state" directly.

### User data layout (`user-data/`, gitignored)

```
user-data/
├─ ledger/events.ndjson       # Append-only event ledger (source of truth)
├─ state/                     # Mutable state: rules, tags, settings, notifications,
│                             #   sync cursors, correlation rules & proposals
├─ secrets/google/            # Your Google OAuth credentials + token
├─ documents/activobank/      # Raw statements (from Gmail or manual upload)
├─ browser/pricempire/        # Persistent Playwright session (cookies)
└─ snapshots/                 # Daily valuation snapshots
```

Move it elsewhere with the `CHRONOLOGS_DATA_DIR` environment variable.
Platform defaults (default categories, suggested-rule templates) live in `server/config/defaults/` and are tracked in git.

## Connectors

### ActivoBank (via Gmail)
Real Gmail API integration (OAuth, `gmail.readonly` scope):

1. **Connections** page → follow the guided steps to create a free Google Cloud project, enable the Gmail API, and create a **Desktop app** OAuth client.
2. Paste the Client ID/Secret, click **Connect Google account**, approve in the browser.
3. **Scan email now** fetches every ActivoBank email + attachment (PDF statements, CSV exports, transaction listings in email bodies), parses them, and builds your transaction history. Re-scans only process new messages; identical documents and transactions dedupe automatically.

**Manual upload**: drop PDF/CSV statements onto the Connections page — same parsing pipeline, for when email invoices are disabled.

### Pricempire (CS2 skins)
Playwright-driven real browser:

1. **Connections** page → **Connect** opens a Chromium window; log in to Pricempire there once. The session persists on disk.
2. **Choose portfolios** scrapes your portfolio list and lets you pick which to import.
3. **Refresh now** (or the scheduler) imports holdings, purchase transactions, and current prices without further intervention. If the session expires, you get a notification asking to re-login.

Site scraping prefers intercepting the site's own JSON responses; all URL patterns/selectors are centralized in `server/ingestion/pricempire/selectors.js` for easy repair after redesigns.

## Organizing: Categories, Tags, Rules

- **Categories** — one per transaction (food, subscriptions, …). Create/merge in the UI.
- **Tags** — many per transaction, user-created groups like `Viagem de férias 2026`. Manage them on the Categories page; filter by tag on Transactions.
- **Rules (Outlook-style)** — ordered list, evaluated top-to-bottom on every new transaction and re-runnable over everything. Conditions: text (contains/equals/regex on description/merchant), date range, amount range, debit/credit, source platform. Actions: set category, add tags. Each rule can **stop processing** of later rules. Manual category choices are never overwritten by rules.
  - Example: rule 1 "spotify → subscriptions, stop" before rule 2 "10/07–25/07 → tag Viagem 2026" means the July Spotify charge is filed as a subscription and *not* tagged as trip spending.
- **Suggested rules** — a built-in Portuguese merchant baseline (Continente, Mercadona, Galp, …) plus, optionally, suggestions generated by your local Ollama model from your real uncategorized transactions (Settings → Local AI). The app is fully functional without the LLM.

## Correlations

Correlation rules link transactions **across platforms** by date proximity and amount tolerance — e.g. a `-100€` ActivoBank debit to CSFloat matched against several Pricempire purchases summing ≈100€ (partial matches supported: money left as site balance). Each find creates a notification; you confirm or reject it on the Rules page. Confirmed links become `transaction_link` events in the ledger.

## Notifications

Internal notification center (bell icon): sync results with counts, unparsed statement lines, correlation proposals, expired sessions, scheduler errors.

## Scheduling

Settings page → per-module refresh frequency (hourly / 6h / daily / weekly / custom cron) driven by an internal scheduler — e.g. ActivoBank weekly, Pricempire several times a day. "Run now" buttons for manual refreshes.

**n8n (optional alternative)**: import the workflows in `n8n/` and disable the corresponding internal schedules if you prefer n8n to drive the refresh endpoints.

## API Highlights

```
POST /api/ingest/activobank            # Gmail scan
POST /api/ingest/activobank/upload     # Manual document upload (multipart)
POST /api/ingest/pricempire            # Portfolio refresh
POST /api/event/manual                 # Manual transaction/asset (with date)

GET/POST/PUT/DELETE /api/rules         # Rules v2 + /reorder /run /suggestions
GET/POST/PUT/DELETE /api/tags          # Tags; /api/transactions/:id/tags to assign
GET/POST /api/correlation-rules        # Correlation rules
POST /api/correlations/run             # + /:id/confirm /:id/reject
GET  /api/notifications                # + /:id/read /read-all
GET/PUT /api/settings                  # Schedules + LLM config
GET  /api/transactions /assets /analytics /events
```

## Design Principles

- **Append-only** — events are never mutated
- **Deterministic** — replaying the same events yields the same projections
- **Idempotent** — content-hash dedup; re-scans, re-uploads and rule re-runs never duplicate
- **Auditable** — every action produces an event (`GET /api/events`)
- **Local-first** — your data never leaves your machine (Gmail/Pricempire are accessed directly from it)
